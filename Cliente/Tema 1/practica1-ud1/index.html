Arquitectura Cliente-Servidor

¿Qué es la Arquitectura Cliente-Servidor?

La Arquitectura cliente servidor es un modelo de diseño de Software donde las funciones de la aplicación se dividen entre dos partes. Uno o varios Clientes que conectan a un mismo servidor para lanzar peticiones y un Servidor central que recibe dichas peticiones, las procesa y devuelve un resultado.

Separar de esta forma la lógica del cliente y el Servidor permite el procesamiento de múltiples peticiones desde un único equipo, reduciendo los requisitos necesarios en el cliente para lanzar las peticiones, aumentando la seguridad de los datos y evita el riesgo de dispersión de los mismos.

Funcionamiento del Modelo

Cliente → Petición (HTTP Request) → Servidor (Procesado) → Respuesta (HTTP Response) → Cliente

Distribución de Tareas

Lado del Cliente (Frontend)

  • Interfaz de usuario.
  • Validación básica de formularios.
  • Dinamismo con JavaScript.

Lado del Servidor (Backend)

  • Procesamiento de lógica pesada.
  • Acceso, consulta y gestión de Bases de Datos.
  • Autenticación de usuarios y seguridad.

Ventajas y limitaciones de JavaScript en cliente

Ventajas:

  • El uso de Javascript en una página permite crear sitios interactivos lo que puede mejorar la experiencia del usuario al navegar.
  • Permite realizar acciones desde el lado del cliente dando una respuesta rápida sin necesidad de recargar la página.
  • Es un lenguaje de programación relativamente fácil de usar.
  • Es compatible con la mayor parte de los navegadores actuales.

Limitaciones

  • Es menos seguro que ejecutar la lógica en el servidor, ya que el código fuente queda expuesto en el navegador.
  • Puede ralentizar el Navegador si el uso es muy pesado.
  • Puede generar problemas de compatibilidad.
  • Un sitio dinámico puede tener problemas de indexados para los bots de los buscadores.
